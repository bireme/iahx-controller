# Replace Poetry with uv

## Context

The project manages Python dependencies with Poetry: `pyproject.toml` uses the legacy
`[tool.poetry]` tables, `poetry.lock` pins the resolution, and the `Dockerfile` does
`pip install poetry` followed by `poetry install` in both the base and dev stages.

We are moving to [uv](https://docs.astral.sh/uv/) for faster installs and resolution, a
standards-based (PEP 621) `pyproject.toml`, and a leaner Docker build. The migration also
moves the runtime from Python 3.12 to **3.14**.

The sibling project `bireme/api-users` has already made this move, so this plan follows its
Dockerfile and `pyproject.toml` conventions rather than inventing new ones.

Outcome: `uv.lock` replaces `poetry.lock`, the image builds with uv, and the existing 58-test
suite still passes. No application code changes, no folder renames.

### The layout trick borrowed from api-users

In `api-users` the uv project root is `/` — `pyproject.toml` and `uv.lock` are copied there,
`uv sync` creates `/.venv`, and only then does `WORKDIR app/` switch to the source directory:

```
/pyproject.toml, /uv.lock, /.venv    <- uv project root (image only)
/app                                 <- source; bind-mounted in dev, COPYed in prod
```

`uv run` from `/app` walks up, finds the project at `/`, and uses `/.venv`. That means the dev
bind-mount can own `/app` completely without shadowing the venv — which is exactly the problem
this project has today. No `UV_PROJECT_ENVIRONMENT`, no `VIRTUAL_ENV`, no `PATH` edits, and no
nested `/app/app`.

Consequences for us:

- `controller/` keeps its name; `docker-compose-dev.yml`'s `./controller:/app` mount is unchanged
- `WORKDIR /app` keeps the flat imports working (`from decode_decs import DecodDeCS`, `uvicorn app:app`)
- `[tool.pytest.ini_options] testpaths = ["controller/tests"]` carries over verbatim

### Decisions taken

| Decision | Choice |
| --- | --- |
| uv in Docker | `COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/`, as in api-users |
| Python version | `requires-python = ">=3.14"`, base image `python:3.14-slim` |
| Dependency location | uv default venv at `/.venv`, used via `uv run` |
| Env-var overrides | none |
| Source layout | unchanged (`controller/` → `/app`) |

The one deliberate divergence from api-users: it uses `python:3.14-alpine`, this project stays
on **`-slim`**, which is what it already uses. The dev group pulls `pandas` and
`mysql-connector-python`, whose musl wheels are patchier; slim avoids a compile toolchain.

### Dependency compatibility on 3.14 (verified against PyPI)

- `pandas 2.3.3` — ships cp314 wheels (2.3.2 does not, so the lower bound must stay at 2.3.3)
- `mysql-connector-python 9.5.0` — ships cp314 wheels (9.4.0 does not)
- everything else (fastapi, redis, requests, loguru, sentry-sdk, pytest, httpx) is pure Python

## Files to change

| File | Change |
| --- | --- |
| `pyproject.toml` | Rewrite as PEP 621 `[project]` + `[dependency-groups]` |
| `poetry.lock` | Delete (`git rm`) |
| `uv.lock` | New, generated by `uv lock` |
| `.python-version` | New, containing `3.14` (matches api-users) |

| `.gitignore` | Add `.venv/` and `__pycache__/` |
| `Makefile` | `dev_test` only — see Step 5 |

`docker-compose.yml` and `docker-compose-dev.yml` are **untouched**: the prod `command:`
override runs from `WORKDIR /app`, and `uv run` is only needed for the entrypoint the
Dockerfile itself defines. (See Step 5 for the one caveat.)

## Step 1 — Rewrite `pyproject.toml`

Poetry carets map to explicit ranges (`^0.115.0` → `>=0.115.0,<0.116.0` for 0.x;
`^5.0.8` → `>=5.0.8,<6.0.0` otherwise).

```toml
[project]
name = "controller"
version = "0.1.0"
description = ""
authors = [{ name = "BIREME" }]
readme = "README.md"
requires-python = ">=3.14"
dependencies = [
    "fastapi[standard]>=0.115.0,<0.116.0",
    "redis>=5.0.8,<6.0.0",
    "requests>=2.32.3,<3.0.0",
    "loguru>=0.7.2,<0.8.0",
    "sentry-sdk[fastapi]>=2.14.0,<3.0.0",
]

[dependency-groups]
dev = [
    "mysql-connector-python>=9.5.0,<10.0.0",
    "pandas>=2.3.3,<3.0.0",
    "pytest>=9.0,<10.0",
    "httpx>=0.28,<0.29",
]

[tool.pytest.ini_options]
testpaths = ["controller/tests"]
```

**No `[build-system]` table** — its absence is uv's equivalent of Poetry's
`package-mode = false`, so uv treats the project as virtual and never tries to build or install
`controller` itself. `api-users` has no `[build-system]` either.

## Step 2 — Generate the lock and pin the interpreter

```
uv lock
git rm poetry.lock
echo 3.14 > .python-version
```

uv fetches a CPython 3.14 toolchain automatically if the machine does not have one.

Add to `.gitignore`:

```
.venv/
__pycache__/
```

## Step 3 — Rewrite the `Dockerfile`

Same shape as `api-users/Dockerfile`: uv installed in base, dependencies synced per stage,
`WORKDIR app/` last.

```dockerfile
########### BASE STAGE ###########
FROM python:3.14-slim AS base

# Set environment variables
ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

# Install uv package manager
COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/

EXPOSE 8000

########### DEV STAGE ###########
FROM base AS dev

# Install dependencies
COPY pyproject.toml uv.lock .
RUN uv sync

# Set app directory
WORKDIR app/

CMD uv run fastapi dev app.py --host 0.0.0.0

########### PRODUCTION STAGE ###########
FROM base AS prod

# Install dependencies
COPY pyproject.toml uv.lock .
RUN uv sync --no-dev

# Set app directory
WORKDIR app/

# Copy src files
COPY ./controller /app/

COPY ./redis_data /redis_data/

# Execute app
CMD uv run uvicorn app:app --host 0.0.0.0 --port 8000 ${APP_RUN_PARAMS}
```

Mapping from the current file:

- `RUN pip install poetry` → `COPY --from=ghcr.io/astral-sh/uv:latest /uv /uvx /bin/`
- `ENV POETRY_VIRTUALENVS_CREATE=false` → dropped; `uv run` finds `/.venv` by walking up from `/app`
- `poetry install --only main` → `uv sync --no-dev` (prod stage)
- `poetry install --with dev` → `uv sync` (dev stage; the `dev` group is included by default)
- the shared `poetry install` in base becomes a per-stage `uv sync`, matching api-users — the
  base stage now only carries the interpreter and uv
- `ENV X 1` updated to the non-deprecated `ENV X=1` form

## Step 4 — `docker-compose.yml` caveat

`docker-compose.yml` overrides the prod CMD:

```yaml
    command: uvicorn app:app --host 0.0.0.0 --port 8000 ${APP_RUN_PARAMS}
```

With no `PATH` override this bare `uvicorn` is not on `PATH`. Two options, pick at
implementation time — **preferred: delete the `command:` line entirely**, since it duplicates
the Dockerfile CMD verbatim and the Dockerfile is now the single source of truth. Otherwise
prefix it with `uv run`, the way `api-users`' dev compose does.

## Step 5 — One Makefile target

`dev_test` calls the container's bare `python`, which is the system interpreter and has no
dependencies installed:

```make
dev_test:
	@docker compose -f $(COMPOSE_FILE_DEV) exec iahx_controller uv run pytest tests/ -v
```

Nothing else in the Makefile changes. Note that `dev_import_decs_redis` and
`import_decs_redis` call a bare local `python`; they were already relying on an ambient
environment and keep working the same way, though `uv run python controller/util/…` would be
the uv-native form if you want it later. `api-users` also has a handy
`dev_update: uv lock --upgrade` target worth adopting at some point.

## Verification

1. `uv lock && uv sync` — resolves and installs cleanly on 3.14.
2. `uv run pytest -v` — all 58 tests pass (same count as before the migration).
3. `make dev_build_no_cache && make dev_start` — image builds from scratch with no poetry layer.
4. `make dev_test` — passes inside the container. Key check that the bind mount at `/app` no
   longer hides the venv, which now lives at `/.venv`.
5. `curl localhost:${APP_PORT}/healthcheck` against the running dev container.
6. Edit a file under `./controller` and confirm `fastapi dev` hot-reloads it.
7. `docker compose build` and `make start` — prod image serves the app.
8. `grep -rn poetry --exclude-dir=.git --exclude-dir=redis_data .` — only the historical
   `.ai` / `ai` documents remain.
